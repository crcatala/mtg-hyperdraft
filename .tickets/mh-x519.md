# Tap to poke: poke ladder, speech bubbles, broadcast to all players

Part of epic mh-uwgh (decisions D1, D2, D4, D9, D12).

## Why
This is the first player-visible payoff: tap any companion and it reacts with a sound, a speech bubble and a motion, escalating through a cycle and ending in a cheeky finale (the old Warcraft/StarCraft "click it too much" gag). Everyone at the table sees and hears it, so it is also the first piece of social interaction, and it establishes the relay pattern and the bubble component that emotes (next ticket) reuse.

## Context
- Companion sprite is currently non-interactive: TableScene.tsx CompanionFigure uses raycast={() => null}.
- Relay template: ClientMessage `point` in src/shared/protocol.ts (zod), STATELESS set + `point` handling in src/worker/roomObject.ts (server stamps `by`, relays to others, no room write), client receive in src/client/net.ts (`case "point"`), sender-side in tableUi.ts (`pingAt` plays locally immediately, then sends; `showPing` is what receivers call). Mirror that shape exactly. Rate limits: src/shared/rateLimit.ts (socket 30/s burst, 5/s sustained).
- The table already uses clicks/keys for pings (Tab pings under the cursor; the table background has a right-click menu "Ping here" in TableScene.tsx ~line 238-250; cards use beginDrag in drag.ts). A poke must not also ping, drag a card or move the camera.
- Kit (lines, slots), voice bank and animation engine come from tickets mh-5c1t, mh-24bx, mh-n7y8.
- src/client/local.ts: solo/local play. Pokes must work there (local only, no network).

## Poke rules (client side, pure + tested; D4)
- Each viewer keeps a ladder per target companion: step 0..6, lastPokeAt.
- A tap advances the step. If > 5 s since the last poke the ladder resets to step 0.
- After step 6 (the finale) the companion sulks: for ~4 s taps are ignored (or give only a tiny wordless reaction, no sound escalation), then the ladder resets to step 0.
- Client throttle ~300 ms between accepted taps.
- Constants exported (IDLE_RESET_MS, SULK_MS, POKE_THROTTLE_MS) so they are easy to tune.

## Work
1. Hit area: an invisible interactive mesh sized to the visible body (not the whole 2.8-unit sprite square); pointer cursor + subtle hover feedback; stopPropagation so the table underneath does not react; does not interfere with orbit/pan/camera controls or card dragging. Right-click is NOT handled here (emote ticket).
2. Pure ladder module (e.g. src/client/table/pokeLadder.ts) + tests.
3. On tap (any player's companion, including bots'): immediately play locally - voice slot poke{step+1} (playVoice, panned by the companion's position on screen, variant pitch), reaction poke{step+1} (playReaction), small bubble with the kit line - then send {t:"poke", target: <playerId>, step}.
4. Protocol: zod `poke` {target: id, step: int 0..6}; ServerMessage `poke` {by, target, step}. Server: verify the target is a seated player who actually has a companion (else drop silently), stamp `by` from the socket, relay to all OTHER sockets, treat as STATELESS (no write budget). Receivers play the same sound/reaction/bubble on the target's companion.
5. Speech bubble component (reused by emotes): billboarded, readable from every seat orientation, small variant here but built with a size prop ("small" | "large"); ~2 s life with pop-in/out; one bubble per companion at a time (a new one replaces the old); wraps long text; pointer-events none; drawn above cards; no layout shift. Do not add Settings toggles here (polish ticket) but route all bubble/voice playback through single functions so a toggle can gate them later.
6. Offline owners: poking a companion whose owner is offline still works.

## Out of scope
Pick-up, right-click wheel, Settings toggles, bot-initiated chatter.

## Acceptance Criteria

- Two real browser sessions: A taps B's companion -> both see and hear the same sound, reaction and bubble line; escalation 1..7 on rapid taps; finale -> sulk -> reset; resets after 5 s idle.
- Poking never pings, drags a card, or moves the camera; works for own, other players' and bots' companions; works in solo/local mode.
- Server drops pokes for unknown targets or targets without a companion, rejects out-of-range steps (zod), never writes room state for pokes, and cannot be spoofed to show another player's `by`.
- Unit tests: ladder (advance, idle reset, sulk lockout, throttle, constants), protocol schema (valid/invalid), room-object relay test if the existing tests allow (follow tests/room.test.ts / presence.test.ts patterns).
- Bubble is readable from all seat orientations (verify with the camera switcher), replaces rather than stacks.
- Verified with agent-browser; screenshots in the PR. `npm run typecheck` and `rtk vitest run` pass.
